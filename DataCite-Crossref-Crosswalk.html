Can the Metadata Game Changers use cases run on Crossref metadata?

Mostly yes, for a reduced catalog. Of the 234 concept scorings across the fourteen use cases, 64 map directly to the Crossref /works response, 71 map approximately, and 99 have no Crossref equivalent. The core FAIR Text and Identifiers concepts, funding, licenses, and most relation types survive the port; contacts, contributor types, typed related items, keywords, and geographic/temporal coverage do not — Crossref’s journal-article heritage shows exactly where you’d expect.

Metadata Connectivity ports better than the completeness catalog. Its questions map almost one-for-one: creator identifiers → author[].ORCID, affiliations → author[].affiliation[].name, affiliation identifiers → affiliation[].id[] (ROR), funder identifiers → funder[].DOI/funder[].id[], rights URIs → license[].URL. The two casualties: publisher identifiers (Crossref identifies the depositing member, not a publisher ROR) and the contributor bars (no contributor-type vocabulary). An Organization Completeness analog also exists: filter=ror-id:<ROR> finds an organization’s works (12,912 for Wageningen), and facet=publisher-name plays the role of the client facet.

Implementation notes for a Crossref port

  • Response shape. Crossref wraps everything in {"message": …}; a work list is message.items[] with fields at the top level — no attributes wrapper. Every jq query needs its path prefix rewritten, and the strict non-empty guards carry over unchanged.
  • Random sampling exists natively. /works?sample=100 returns a true random sample (max 100 per call) — repeat and dedup by DOI, the same pattern the tools already use for DataCite's random=true.
  • Organization Completeness analog. filter=ror-id:<ROR> selects works carrying the organization's ROR (12,912 for Wageningen today vs 6,764 in DataCite), and facet=publisher-name or facet=funder-doi can play the client-facet role. Note the population is ~0.6% of works so far — publisher-asserted RORs are young in Crossref.
  • Filters compose like DataCite query params: filter=type:journal-article,from-pub-date:2024-01-01,has-orcid:true. Counts come free from total-results with rows=0.
  • Abstracts are JATS XML — strip tags before value drill-downs and length checks.
  • Be polite. Add mailto= to every request (or a User-Agent) to reach the polite pool; page with cursor=* for deep result sets.
  • Vocabulary crosswalks needed. type (30 values) → resourceTypeGeneral, and Crossref relation keys (is-supplement-to…) → DataCite relationTypes are mechanical renames; both are enumerated in this page's CSV companion.
  • What a Crossref catalog would drop. Keywords (subjects retired 2024), geographic and temporal coverage, typed descriptions beyond the abstract, sizes/formats, view/download counts, contact roles, and the contributor-type vocabulary. A sensible port scores a reduced catalog rather than reporting structural zeros for concepts Crossref cannot express.
DataCite side: Metadata Game Changers use-case catalog (FAIR_spirals.json, strict-empty semantics of 2026-08-24), 234 concept scorings over 14 use cases, 159 distinct concepts. Crossref side: verified against the live REST API (api.crossref.org, 186.3M works) on 2026-09-06 — field structures inspected on real records; coverage counts from filter totals; relation-type usage sampled from 1,000 works with relations. Statuses: direct = an equivalent field exists · partial = an approximation or a sparsely-used equivalent · unmapped = Crossref cannot express it. A Metadata Game Changers working document.
